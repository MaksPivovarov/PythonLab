# Лабораторная работа №7 — вариант 11, «Такси»


`problem_version.py` содержит намеренно проблемный вариант: класс одновременно отвечает за ввод, бизнес-логику, хранение и вывод.

Основная реализация находится в `solid_app.py` и разделена на модели, репозитории, стратегии расчёта, уведомления и сервис.

- SRP: отдельные модель, репозитории, тарифы, уведомления и сервис.
- OCP: новые тарифы добавляются отдельными классами `FareStrategy`.
- LSP: `InMemoryRideRepository` и `JsonRideRepository` взаимозаменяемы.
- ISP: небольшие Protocol `RideRepository` и `Notifier`.
- DIP: `RideService` получает репозиторий, уведомления и тариф через конструктор.

Запуск приложения:

```text
python main.py
```

Запуск тестов:

```text
python test_solid.py
```
