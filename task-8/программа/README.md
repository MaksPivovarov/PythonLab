# Лабораторная работа №8, вариант 11: Такси

## Наивная версия
`naive_version.py` использует ветвления для каждого тарифа и типа автомобиля. При добавлении нового тарифа приходится менять расчётчик, который также знает о разновидностях машин. Это затрудняет расширение и тестирование.

## Паттерны

- **Repository**: `InMemoryRepository` и `FileRepository` реализуют один интерфейс. `TaxiService` не зависит от конкретного хранилища.
- **Strategy**: `StandardFare`, `NightFare` и `SurgeFare` инкапсулируют алгоритмы расчёта. Их можно менять независимо от сервиса.
- **Factory**: `CarFactory` создаёт допустимый класс автомобиля, `FareFactory` выбирает стратегию тарифа.
- **Observer**: журнал, уведомления и статистика получают события о создании, отмене и перерасчёте поездки.
- **Command**: команда создания заказа поддерживает отмену через `undo()`.

Factory вместе со Strategy полезны здесь потому, что сначала по названию тарифа выбирается алгоритм, а тип автомобиля отдельно проверяется и преобразуется. Добавление нового тарифа не требует менять код сервиса.

## Запуск

```text
python main.py
python test_patterns.py
```

Приложение позволяет выбрать хранение в памяти или в JSON-файле.
